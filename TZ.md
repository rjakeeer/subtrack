# Техническое задание на проект: SubTrack — Сервис учета цифровых подписок

## 1. Цель проекта
Создание веб-сервиса для централизованного учета цифровых подписок (стриминг, софт, игры, облачные хранилища). Проект решает проблему неконтролируемых трат на периодические платежи. Система помогает пользователю анализировать расходы, наглядно визуализирует структуру затрат по категориям с помощью графиков и предлагает простые текстовые рекомендации по оптимизации бюджета.

## 2. Роли пользователей
* **Гость:** Имеет доступ к главной странице с описанием возможностей сервиса, может зарегистрироваться или войти в систему. Доступ к финансовым данным закрыт.
* **Авторизованный пользователь:** Обладает полным доступом к личному кабинету. Может добавлять, редактировать и удалять свои подписки, просматривать аналитику расходов и графики, сгенерированные системой лично для него.

## 3. Модели данных (сущности)
В системе реализуются 3 кастомные модели данных (не считая стандартной модели User в Django):

1. **Category (Категории подписок)**
   * Предназначена для группировки сервисов (например: "Стриминг", "Работа", "Гейминг").
   * *Поля:* `name` (название), `slug` (уникальный URL).

2. **SubscriptionService (Каталог сервисов)**
   * Базовый справочник популярных подписок для быстрого выбора пользователями (например: Яндекс Плюс, Иви, VK Музыка).
   * *Поля:* `name` (название), `category` (связь ForeignKey с моделью Category), `default_price` (базовая стоимость).

3. **UserSubscription (Подписки пользователя)**
   * Главная сущность, связывающая конкретного пользователя с его персональными параметрами подписки.
   * *Поля:* 
     * `user` (связь ForeignKey с моделью User — обеспечивает разделение прав доступа);
     * `service` (связь ForeignKey с SubscriptionService, может быть Null, если пользователь вводит свой вариант);
     * `custom_name` (кастомное имя, если сервиса нет в каталоге);
     * `price` (фактическая стоимость подписки для пользователя);
     * `billing_period` (периодичность: месяц / год);
     * `next_billing_date` (дата следующего списания);
     * `is_active` (статус подписки: активна / на паузе).

## 4. Ключевой функционал (User Stories)
* **Управление подписками (CRUD):** Пользователь через валидные Django-формы может добавлять новые подписки (выбирая из каталога или вводя вручную), изменять их параметры (цену, статус) или удалять их.
* **Контроль платежей:** Отображение на дашборде списка ближайших списаний, отсортированных по дате, для предотвращения забытых платежей.
* **Аналитический блок:** Расчет суммарных трат пользователя за текущий месяц и линейный прогноз базовых расходов на год вперед с использованием агрегации Django ORM (`Sum`).

## 5. Аналитика и визуализация
* **Генерация графиков (Бэкенд):** Использование встроенной Python-библиотеки **Matplotlib** для анализа данных из БД и построения круговой диаграммы (Pie Chart). Диаграмма наглядно демонстрирует процентное распределение ежемесячных расходов пользователя по категориям. График генерируется на сервере и передается в HTML-шаблон в виде изображения.
* **Логика оптимизации затрат:** Простой алгоритм на Python, который анализирует активные подписки пользователя. Если в одной категории (например, "Музыка") обнаруживается более одной активной подписки, система выводит в личном кабинете предупреждение о потенциально избыточных тратах.
